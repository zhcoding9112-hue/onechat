# Proposal

## Why

现有系统按「公会私域收银台」定位实现完毕：粉丝指名下单、人工收款、分成记账、履约追踪，109 项任务全部交付。但产品负责人对标竞品「陪一」后判定，当前形态不足以支撑增长——它只服务已经认识某位主播的粉丝，没有任何让新粉丝发现主播的路径，也没有任何提高停留与复访的内容与玩法。

因此调整方向：从只做收银，转为做撮合。粉丝既能指名下单，也能通过浏览、筛选、随机匹配、试音、榜单、动态发现主播。本次变更补齐这条发现链路与配套的互动、运营玩法，并把粉丝端视觉整体重做到可对外的水准。

## What Changes

- **粉丝端首页重做为发现版面**：品类 Tab 横滑、双入口大卡（发现 / 随机盲盒）、打赏跑马灯、人气店员横滑、九宫格服务入口、运营横幅轮播、试音选人入口、带筛选的主播信息流。
- **主播卡片信息扩展**：封面图、语音试听时长角标、性别、年龄、地区、在线状态、能力标签行、两个自由填写的宣传语标签、收藏入口。**BREAKING**：`talent` 表新增性别、年龄、地区字段，主播资料接口返回结构变更。
- **主播列表支持筛选与排序**：按性别、按等级筛选，无限下拉加载。
- **新增收藏能力**：粉丝可收藏主播，在个人中心查看收藏列表。
- **新增随机匹配**：随机盲盒与心动盲盒，按条件随机匹配一位主播并引导下单。这是随机派单，不是抽奖。
- **新增试音选人**：粉丝浏览主播试听片段挑人，或发布试音需求由主播应征。
- **新增内容社区**：动态广场与心动墙，主播发布动态、粉丝浏览与互动。
- **新增站内聊天**：粉丝与主播在站内即时沟通，替代部分站外微信沟通。
- **新增榜单与等级**：日/周/月打赏榜，Top3 领奖台，粉丝等级体系。
- **新增优惠券与券包**：运营发券、粉丝领券、下单抵扣。
- **新增元子余额记账**：展示余额与流水，由运营手工发放与调整。**不开放用户充值，不开放提现。**
- **视觉整体重做**：粉丝端全部页面按竞品观感重做配色、排版、组件样式；2026-11-22 用户允许参考或复制竞品素材，实际素材逐项登记来源。
- **埋点扩展**：每个新增入口单独埋点，漏斗可按入口拆分归因。

### 不在本次范围内

- **电竞分区**。服务目录暂不引入业务分区维度，表结构预留扩展位。
- **用户充值与提现**。元子只记账，真实充值涉及预付资金沉淀，另案决策。
- **自建音视频通话**。通话继续在站外发生。
- **营销文案与封面图烧字模板**。宣传语标签、简介、封面图一律由运营与主播自填，系统只提供字段与审核开关，不内置任何文案模板，不提供在封面图上合成文字的功能。
- **主播端工作台与运营后台的视觉改版**。两者是内部工具，沿用现有样式。

## Capabilities

### New Capabilities

- `discovery-home`: 粉丝端首页发现版面。各入口区块的组织、排序、数据来源与可配置性。
- `talent-favorites`: 粉丝收藏主播，收藏列表的查看与取消。
- `random-match`: 随机匹配。按条件随机选出一位可接单主播并引导下单，含匹配条件与排除规则。
- `voice-audition`: 试音选人。按试听片段挑选主播，以及发布试音需求与主播应征。
- `social-feed`: 内容社区。动态广场与心动墙的发布、浏览、互动与运营下架。
- `in-app-chat`: 站内即时沟通。会话列表、消息收发、未读计数。
- `leaderboard`: 榜单与粉丝等级。按周期的打赏榜计算、展示与等级规则。
- `promotion-coupon`: 优惠券与券包。券的定义、发放、领取、使用与失效。
- `credit-ledger`: 元子余额记账。余额展示、流水记录、运营手工发放与调整。

### Modified Capabilities

- `talent-catalog`: 主播资料新增性别、年龄、地区、宣传语标签；列表新增筛选、排序与分页加载；详情页新增收藏状态。
- `analytics-funnel`: 新增各发现入口的埋点节点，漏斗支持按入口来源拆分归因。
- `tipping`: 打赏结果需驱动榜单计算与首页跑马灯展示。

## Impact

- **数据存储**：`talent` 表新增字段；新建收藏、动态、评论、会话、消息、榜单快照、等级、优惠券、券包、元子流水等表。
- **接口**：主播列表与详情接口返回结构变更，前端需同步；新增各能力的读写接口。
- **前端**：粉丝端全部页面重做视觉；首页由单一列表改为多区块版面；新增多个页面与路由。
- **运营流程变更**：新增动态与心动墙的内容审核、优惠券发放、元子手工调整、榜单周期结算等例行工作。
- **合规与风险**：引入 UGC（动态、心动墙、站内聊天）后，内容审核义务落到平台方，需配套举报与下架能力。元子只记账不充值是为避开预付资金沉淀。
- **工期**：本次范围远大于上一个 change，不应作为一个批次交付，tasks 按组划分优先级，建议分批上线。
