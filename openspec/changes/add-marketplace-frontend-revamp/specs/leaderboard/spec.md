# Spec Delta

## Purpose

以周期榜单呈现主播的打赏收入排名并给予粉丝等级反馈，为打赏提供可见的即时回报。

## ADDED Requirements

### Requirement: 周期打赏榜

系统 SHALL 提供日榜、周榜、月榜三种周期的主播打赏榜。排名 MUST 基于对应周期内已确认收款的打赏金额合计，MUST NOT 计入未确认或已退款的打赏。

#### Scenario: 查看日榜

- **WHEN** 粉丝打开榜单页并选择日榜
- **THEN** 系统展示当日已确认打赏金额前列的主播及其排名

#### Scenario: 退款的打赏不计入

- **WHEN** 一笔已计入榜单的打赏被标记退款
- **THEN** 该金额从对应周期的排名计算中扣除

#### Scenario: 周期切换

- **WHEN** 进入新的统计周期
- **THEN** 新周期的榜单从零开始计算
- **AND** 上一周期的榜单结果被固化保存

### Requirement: 榜单展示规则

系统 SHALL 以领奖台形式突出展示前三名，第四名起以列表展示。榜单 MUST 展示主播昵称、头像与排名，MUST NOT 展示任何打赏人的身份信息。

#### Scenario: 前三名展示

- **WHEN** 粉丝打开榜单
- **THEN** 前三名以领奖台形式展示，第四名起为列表

#### Scenario: 不泄露打赏人

- **WHEN** 任意粉丝查看榜单
- **THEN** 展示内容中不含任何打赏人的昵称、头像或标识

#### Scenario: 榜单为空

- **WHEN** 当前周期尚无任何已确认打赏
- **THEN** 系统展示空状态，不展示错误页

### Requirement: 粉丝等级

系统 SHALL 依据粉丝的累计已确认消费金额计算其等级。等级门槛 MUST 后台可配。等级 MUST NOT 影响下单价格与分成计算。

#### Scenario: 等级提升

- **WHEN** 粉丝的累计已确认消费金额越过某一等级门槛
- **THEN** 系统将其等级提升并在个人中心展示新等级

#### Scenario: 运营调整门槛

- **WHEN** 运营在后台调整等级门槛
- **THEN** 此后的等级计算按新门槛执行

#### Scenario: 等级不影响计价

- **WHEN** 不同等级的粉丝对同一主播同一档位下单
- **THEN** 两笔订单的金额与分成快照完全一致
