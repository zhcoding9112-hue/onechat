# Spec Delta

## Purpose

以「元子」为单位记录粉丝账户的余额与流水，供运营做补偿、奖励与差错调整，并为后续可能开放的充值保留账务基础。

## ADDED Requirements

### Requirement: 余额与流水记账

系统 SHALL 为每位粉丝维护一个元子余额及其完整流水。每笔余额变动 MUST 产生一条流水，记录变动金额、变动后余额、类型、操作者与时间。余额 MUST 以整数记录，MUST NOT 使用浮点。

#### Scenario: 查看余额与流水

- **WHEN** 粉丝打开个人中心的元子页
- **THEN** 系统展示其当前余额与按时间倒序的流水记录

#### Scenario: 每笔变动都有流水

- **WHEN** 粉丝余额发生任意一次变动
- **THEN** 系统生成一条对应流水，含变动金额与变动后余额

#### Scenario: 余额不可为负

- **WHEN** 某次扣减会使余额低于零
- **THEN** 系统拒绝该次扣减并保持余额不变

### Requirement: 运营手工发放与调整

系统 SHALL 只允许运营手工发放或调整粉丝余额，且 MUST 填写原因。系统 MUST NOT 向粉丝开放任何充值入口。

#### Scenario: 运营发放

- **WHEN** 运营为某粉丝发放 50 元子并填写原因
- **THEN** 该粉丝余额增加 50，流水记录操作者与原因

#### Scenario: 调整需填原因

- **WHEN** 运营提交一次余额调整但未填写原因
- **THEN** 系统拒绝该操作并提示原因为必填

#### Scenario: 粉丝无充值入口

- **WHEN** 粉丝浏览元子页与个人中心的任意位置
- **THEN** 系统不展示任何充值、购买或兑换入口

### Requirement: 不开放提现

系统 MUST NOT 提供任何将元子余额提取为现金的功能。元子 MUST NOT 可转让给其他粉丝。

#### Scenario: 无提现入口

- **WHEN** 粉丝查看元子页
- **THEN** 系统不展示提现入口

#### Scenario: 不可转让

- **WHEN** 粉丝尝试将余额转给另一位粉丝
- **THEN** 系统不提供该能力
