# Spec Delta

## Purpose

让粉丝与主播在站内完成下单前的沟通，减少过早转向站外微信造成的流失与不可追溯。

## ADDED Requirements

### Requirement: 会话与消息收发

系统 SHALL 为粉丝与主播之间建立一对一会话，支持文字与图片消息。消息 MUST 记录发送者、接收者与发送时间，MUST 按时间顺序展示。

#### Scenario: 发起会话

- **WHEN** 粉丝在主播详情页点击聊天
- **THEN** 系统建立或打开与该主播的会话

#### Scenario: 发送消息

- **WHEN** 粉丝在会话中发送一条文字消息
- **THEN** 系统保存该消息并在双方会话中按时间顺序展示

#### Scenario: 对已下架主播的会话

- **WHEN** 粉丝打开与一位已下架主播的历史会话
- **THEN** 系统展示历史消息
- **AND** 禁用发送入口并说明该主播暂不可约

### Requirement: 会话列表与未读计数

系统 SHALL 提供会话列表，按最后一条消息时间倒序排列，并展示每个会话的未读消息数。打开会话后 MUST 将其未读数清零。

#### Scenario: 查看会话列表

- **WHEN** 粉丝打开会话列表
- **THEN** 系统按最后消息时间倒序展示全部会话及各自未读数

#### Scenario: 打开后未读清零

- **WHEN** 粉丝打开一个有未读消息的会话
- **THEN** 该会话未读数归零

#### Scenario: 全局未读提示

- **WHEN** 粉丝存在任意未读消息
- **THEN** 底部导航的聊天入口展示未读标记

### Requirement: 聊天内容留存与处置

系统 SHALL 留存聊天消息供纠纷追溯，并为运营提供按会话查看与对违规消息的处置能力。粉丝与主播 MUST NOT 能删除对方已收到的消息。

#### Scenario: 运营查看会话

- **WHEN** 运营因纠纷在后台按订单或用户查找会话
- **THEN** 系统展示该会话的完整消息记录

#### Scenario: 不可单方删除

- **WHEN** 粉丝尝试撤回一条对方已收到的消息
- **THEN** 系统拒绝该操作
