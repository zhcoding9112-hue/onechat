# 运营手册

这份手册面向每天实际操作系统的人，不需要任何技术背景。
按步骤做即可；遇到手册没写的情况，先别猜，找技术确认。

后台地址：`https://你的域名/admin`（需用运营账号，在微信里打开）

---

## 一、每日对账（必做）

人工收款期间，**钱到账后订单不会自动往下走，必须有人核对并确认**。
每天至少做一次，建议固定时间，比如每天上午十点。

### 步骤

1. 打开后台 →「转化看板」，先看一眼当天数据是否正常。
2. 打开**公司对公账户的流水**（网银或银行 App）。
3. 打开后台 →「收款与对账」→「待对账」页签。列表里是粉丝已上传凭证、
   等着你核对的订单，每行带主播、服务、应收金额和凭证缩略图（点图可放大）。
4. 对每一笔：
   - 看凭证图片上的金额和时间
   - 到银行流水里找**对应金额的到账记录**
   - 流水备注里应当有订单号。找不到订单号时，用金额 + 时间比对
5. 流水里**确实有这笔钱**：点「确认收款」
   - 实收金额填**银行流水上的实际金额**，不是订单应付金额
   - 两者不一致时系统会要求填写差异说明，必须写清楚原因
     （例如「粉丝少付 1 元，已沟通补足」）
6. 流水里**没有这笔钱**：点「驳回」，填写原因
   - 订单会退回待支付，粉丝可以重新上传凭证
   - 驳回原因粉丝看得到，写清楚一点，例如「未在账户中查到该笔到账，请确认是否转账成功」

### 要点

- **以银行流水为准，凭证只是辅助定位。** 凭证截图是可以伪造的，到账记录不能。
- 确认收款后，系统会立刻通知主播接单，并开始计算接单时限。所以**别攒着一起确认**，
  攒一天再确认会让粉丝白等一天。
- 确认和驳回都会记录是谁、什么时候操作的，出问题可以追溯。

### 打赏也要在同一轮里对

订单对完，再去后台 →「打赏管理」→「待处理」。打赏和订单走的是两条队列，
对账时容易漏掉。两点不同：

- 打赏**没有凭证**可看，只能靠金额 + 时间 + 粉丝昵称去银行流水里比对。
- 确认后**直接计为已完成**，不会通知主播接单——主播什么也不用做。

发起了一直不付款的，点「取消」清掉（打赏没有超时回收，不清就一直挂着）。
已经确认收款又要退的，在「记录」页点「标记退款」：那只冲销台账和榜单，
**钱要你自己转回去**。

## 二、退款处理

### 什么时候会有退款

| 情况 | 系统状态 | 怎么来的 | 要退钱吗 |
| --- | --- | --- | --- |
| 主播超时未接单 | 已超时 | 系统自动置为超时，并放进待退款队列 | **要**，钱已经收了 |
| 粉丝下单后没付款 | 已取消 | 系统自动取消，不进队列 | 不用，压根没收到钱 |
| 粉丝申请取消 | 需人工取消 | 你在后台手动取消 | 看是否已确认收款 |
| 服务纠纷 | 已完成后退款 | 你在后台手动标记退款 | 要 |

两种超时去向不一样，别搞混：没付款的直接「已取消」，付了款没人接的才叫
「已超时」，只有后者进待退款队列。

### 步骤

1. 后台 →「订单管理」→「待退款」页签。里面是系统自动判定需要退款的订单
   （付了款但主播超时未接单），页面顶部会算出队列里一共压着多少钱。
2. **先在银行把钱退给粉丝**，走对公账户转账，备注写订单号。
3. 退款到账后，回系统点「标记退款」，填写原因。
4. 系统会把这笔订单的分账**冲销**——也就是这笔钱不再计入主播当月的应得。

### 要点

- **系统不会自动退钱。** 它只负责告诉你该退哪些、记录你退了没有。实际转账是人工动作。
- 顺序不能反：先退钱，再标记。反过来的话，万一转账失败，系统里却显示已退款，账就乱了。
- 重复点「标记退款」不会重复记账，放心。
- **粉丝申请取消时，先看「轨迹」。** 「订单管理 → 全部订单」每行都有，
  能看到这一单从创建到现在谁动过、什么时候、原因写了什么。说不清的纠纷，
  先看轨迹再下结论。
- 取消已经收过款的订单，系统**不会**自动退钱，弹窗里会提醒。该退的还是要
  走上面那套：先转账，再回来标记。

## 三、常见异常处置

### 粉丝说「付了钱但订单还是待支付」

1. 问粉丝有没有**上传凭证**。很多人转完账就关掉了页面。
   - 没传：让他回订单详情页点「去付款」，上传转账截图
   - 传了：说明在「待对账」页签里，去确认即可
2. 到银行流水里核对。钱确实到了就确认收款；没到就让粉丝检查转账是否成功。
3. 钱已到账、但粉丝就是不肯回来传凭证：到「待支付」页签找到这一单，
   直接点「确认收款」，不必等他补凭证。流水号务必填上，这是日后对账的唯一线索。

### 粉丝说「主播一直不接单」

1. 看订单状态：
   - **待接单** → 看剩余接单时间。时限内属正常，提醒主播即可
   - **已超时** → 进入退款流程（见上）
2. 联系主播。接单率是我们的关键指标，连续不接单要及时沟通。

### 主播说「看不到订单」

按顺序检查：

1. 主播的微信号**有没有关联到主播档案**？后台 → 主播 → 找到他 → 看「关联账号」
   - 没关联：关联上，他下次打开就能进工作台
2. 他是不是**用错了微信号**？关联的是 A 号，他用 B 号打开，当然看不到
3. 订单是不是**还没确认收款**？没确认收款的订单不会出现在待接单列表里

### 主播说「在线状态改不了」

让他在工作台 →「我的」里切换。如果开关点了没反应，多半是网络问题，让他刷新重试。

### 粉丝说「打不开页面」「提示请在微信中打开」

本系统**只能在微信里打开**。用 Safari、Chrome 或其他浏览器访问会看到引导页。
让粉丝从公众号菜单或聊天里的链接进入。

### 看板上接单率标红了

这是重要信号，不是小问题。接单率低意味着：

- 粉丝付了钱却等不到服务，体验极差
- 更要命的是，**此时的转化率数据不可信**——它会把「主播没接单」
  误记成「产品没转化」，照着这个数据做优化等于南辕北辙

处置：看板 →「按主播拆分」，找出接单率低的是谁，单独沟通。

## 四、日常配置

### 改价格

后台 →「服务与价格」→ 找到档位 →「配价」。

**改价不影响已经下过的单。** 每笔订单在创建那一刻就把价格写死了，之后怎么改都不回溯。

### 改分成比例

后台 →「分成比例」。可以设全局默认，也可以给某位主播单独设。

同样**只对新订单生效**，已创建的订单按下单时的比例结算。

### 上下架主播

后台 → 主播 →「上架 / 下架」。

下架后粉丝端看不到他、不能对他下新单，但**他手上没做完的订单不受影响**，
仍然可以正常接单和完成。

### 改接单时限

后台 → 订单 →「时限配置」。改完立即生效，不需要重启。

同样**只影响之后创建的订单**，正在计时的订单沿用原来的时限。

## 五、月底结算

1. 后台 →「结算报表」→ 选择月份（默认当月，不用「生成」，选完即出）
2. 报表按主播逐行，服务订单金额和打赏金额分开列，给出公会分成与主播应得
3. 点「导出 CSV」下载，用 Excel 打开核对
4. 对某位主播的金额有疑问时，点「明细」看逐笔分账，每一行都能手工验算
   （算法见 `docs/settlement.md`）；明细也能单独导出
5. 按既有流程**线下把钱打给主播**
6. 打完款回系统，点该行的「标记结清」，可以把转账流水号填在备注里

### 要点

- 系统**不提供提现、打款或任何资金划转**。它只记账，钱怎么给还是走原来的流程。
- 「已结清」只是个记号，标错了可以撤销，不会影响任何金额。
- 报表里**没有流水的主播也会出现，各项为零**。这是故意的——方便你一眼看出
  这个月谁一单都没有。人多了嫌吵，勾上「只看有流水的」。
- **「公会分成」不是公会实收。** 券的抵扣记在「促销成本」里由公会承担，
  不从主播应得里扣。页面顶部的「公会实得」已经减过了，看那个数。
- 退过款的订单与打赏**不计入合计**，但在明细里仍然列出并标明原因，
  方便事后追溯。

## 六、看满意度（建议每周一次）

后台 →「满意度回访」。粉丝在订单完成后给 1 到 5 分，每单一次、评完不能改。

**这一页按均值从低到高排，低分在最前**，所以从上往下看就行。看三件事：

1. **全站低分（1–2 分）的条数**。有就点进去逐条看。
2. **均值低于 3 分的主播**（标红）。两三条评分就跌到 3 分以下的，
   多半是真出了问题，不是运气差。
3. **评分数还是 0 的主播**。不一定是坏事，可能只是单少。

### 看到低分之后

1. 点那一行的「逐条看」，拿到**订单号**。
2. 把订单号粘到「订单管理 → 全部订单」的搜索框，找到那一单。
3. 点「轨迹」，看这一单实际发生了什么：什么时候接的单、隔了多久完成的、
   中间有没有被取消过。
4. 判断该怎么办：确实是服务问题就联系主播；粉丝觉得不值就考虑退款
   （在同一页点「标记退款」，钱仍要人工转）。

### 要点

- **评分不在粉丝端公开**，其他粉丝看不到任何分数，所以低分不会直接伤到主播的单量。
  正因为如此，**发现问题全靠你主动来看**——没人会替你盯。
- 主播本人在工作台能看到自己的分和均值。跟主播沟通时可以直接引用，他看得到同一个数。
- 粉丝那一栏只有 id，没有昵称。要联系粉丝，从订单那边拿微信号。

## 七、什么时候该找技术

以下情况不要自己处理，直接找技术：

- 页面打开报错、白屏
- 后台操作提示「服务暂时不可用」
- 金额对不上，且按 `docs/settlement.md` 手算也对不上
- 同一笔钱在系统里出现了两次
- 看板数据明显不合常理（比如转化率超过 100%）

> 转化率超过 100% 通常意味着上游某个节点漏埋了，是个真实问题，值得查。
