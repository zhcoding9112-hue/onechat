# 开局配置操作手册

把剩下的待办拆成可以照着做的步骤。日常运营（每天怎么对账、怎么处理纠纷）在
`docs/ops-runbook.md`，这一份只管**上线前把东西配起来**。

---

## 先说一件要紧的事：有六块运营能力没有后台页面

动手之前你得知道哪些事现在点得到、哪些点不到。我把后端的运营接口和后台实际
接入的页面逐一对了一遍：

| 要做的事 | 后端接口 | 后台页面 |
| --- | --- | --- |
| 主播文字资料、上下架 | 有 | ✅ 主播管理 |
| 服务项目与价格 | 有 | ✅ 服务与价格 |
| 分成比例 | 有 | ✅ 分成比例 |
| 优惠券 | 有 | ✅ 优惠券 |
| 粉丝等级门槛 | 有 | ✅ 粉丝等级 |
| 元子记账 | 有 | ✅ 元子记账 |
| 内容审核、心动墙 | 有 | ✅ 内容审核 |
| 会话查询 | 有 | ✅ 会话查询 |
| 转化看板 | 有 | ✅ 转化看板 |
| **填收款账号** | 有 | ❌ **没有页面** |
| **每日待对账、确认收款** | 有 | ❌ **没有页面** |
| **上传封面图与试听片段** | 有 | ❌ **没有上传控件** |
| **订单管理（取消、退款）** | 有 | ❌ **没有页面** |
| **打赏管理（确认、退款、上限）** | 有 | ❌ **没有页面** |
| **结算报表（月度分账）** | 有 | ❌ **没有页面** |
| **首页运营位** | 有 | ❌ **没有页面** |
| **满意度回访查看** | 有 | ❌ **没有页面** |

最要命的是第二行。**人工收款模式下，钱到账后订单不会自动往前走，必须有人在
后台点「确认收款」**；没有这个页面，线上任何一笔订单都会永远卡在待支付/待确认，
主播接不到单。`docs/ops-runbook.md` 第一章让运营「打开后台的待对账列表」——
那个列表目前并不存在。

### 为什么一直没被发现

因为后端这些接口**全都有测试覆盖、而且都是走真实 HTTP 接口测的**。
第 14 组那八条端到端验收也一样：它们直接请求 `/api/admin/payment/{id}/confirm`，
接口返回什么、金额对不对、状态怎么流转，全都验到了。

但「这个接口在后台有没有一个按钮」，接口测试永远测不到。
我写验收用例时特意强调「不走捷径调 service，全部经过真实 HTTP 接口」——
这话没错，可它挡住的是服务层的接缝，不是前端缺页面。

下面的步骤里，**没有页面的事我给 curl 命令**，并标注这是临时办法。

## 一、现在就能在后台点的

后台地址 `https://你的域名/admin`，需要运营角色，在微信里打开。

### 1. 服务与价格（最先做，别的都依赖它）

菜单「服务与价格」。

1. **建服务项目**：填「编码」（英文短名，如 `listen`，建后不要再改——
   首页品类 Tab 按它筛选）、「名称」（如 情感倾听）、「说明」、「排序」。
2. **给项目建档位**：填「档位」编码、「名称」（如 30 分钟）、「时长」（分钟）、「排序」。
3. **给主播设价**：填「主播 ID」、选档位、填「单价」、置为启用。

> 价格在粉丝下单那一刻快照进订单，之后改价不影响已有订单。

### 2. 主播管理（文字资料部分）

菜单「主播管理」→「新建主播」。可填：昵称（必填）、性别、年龄、地区、简介、
宣传语标签（最多 2 条）、排序。

列表的「素材」列会标出「缺封面」「缺试听」——**但这个页面没有上传控件**，
传图传音频见第二部分第 3 条。

建完先别急着上架。**上架前确认：有价格、有封面、有试听**，否则粉丝端卡片会留白。
上架用列表里的「上架」按钮。

### 3. 分成比例

菜单「分成比例」。默认 30%。改动**只影响此后的新订单**——已有订单的分成在下单
那一刻就快照了，不会被追溯修改。

### 4. 粉丝等级门槛

菜单「粉丝等级」。现在是我填的占位值，名字就叫 L1–L5：

| 等级 | 名称 | 累计消费门槛 |
| --- | --- | --- |
| 1 | L1 | 0 元 |
| 2 | L2 | 200 元 |
| 3 | L3 | 1000 元 |
| 4 | L4 | 3000 元 |
| 5 | L5 | 10000 元 |

改「名称」和「累计消费门槛（元）」即可。规则：等级 1 的门槛必须是 0，
门槛必须逐级递增。等级只影响展示，不影响下单价格与分成。

### 5. 优惠券

菜单「优惠券」→ 新建。填：券名、面额、使用门槛、有效期（生效 / 失效时间）。
建完在列表里「发放」，可发给全体粉丝或指定用户。

> 门槛按**订单原价**判定，券只减粉丝实付，主播分成一分不少，差额由公会承担。
> 单笔订单只能用一张券。

### 6. 心动墙

菜单「内容审核」→「心动墙」页签。按主播 ID 挑人、设排序。本阶段只有手工挑选。

## 二、后端有接口、但后台还没页面的

以下都要用命令行。**这是临时办法**，正式做法是把页面补上（见第三部分）。

先拿一个运营身份的会话 Cookie。本机开发环境：

```bash
UA="Mozilla/5.0 (iPhone; MicroMessenger/8.0.49)"
LOC=$(curl -s -i -c pc.cookie -A "$UA" \
  "http://127.0.0.1:8080/api/auth/wechat/authorize?redirect=/" \
  | grep -i '^Location:' | tr -d '\r' | sed 's/^Location: //')
curl -s -o /dev/null -b pc.cookie -c pc.cookie -A "$UA" "$LOC"
curl -s -b pc.cookie -A "$UA" http://127.0.0.1:8080/api/session/me
```

线上环境没有这个授权桩，得用真实微信登录后从浏览器里取 `PCSESSION` 的值，
后面的命令都带上 `-b "PCSESSION=取到的值"`。

### 1. 填真实收款账号（清单 A1，上线前必做）

```bash
curl -s -b pc.cookie -X PUT \
  -H 'Content-Type: application/json' \
  -d '{"accountName":"真实户名","accountNo":"真实账号",
       "bankName":"开户行","qrUrl":null,
       "tips":"转账时请务必在备注里填写订单号。"}' \
  http://127.0.0.1:8080/api/admin/payment/settings/manual
```

改完**自己转一笔小额过去验证真的能到账**，别只看页面显示正常。

查看当前值：`curl -s -b pc.cookie http://127.0.0.1:8080/api/admin/payment/settings`

### 2. 每日对账与确认收款（日常天天要用）

```bash
# 待对账列表：粉丝已上传凭证、等你核对的订单
curl -s -b pc.cookie http://127.0.0.1:8080/api/admin/payment/reconcile

# 核对银行流水后确认收款（金额按实际到账填，单位：分）
curl -s -b pc.cookie -X PUT -H 'Content-Type: application/json' \
  -d '{"paidCents":18000,"externalRef":"银行流水号"}' \
  http://127.0.0.1:8080/api/admin/payment/订单ID/confirm

# 对不上账时驳回
curl -s -b pc.cookie -X PUT -H 'Content-Type: application/json' \
  -d '{"reason":"未查到对应到账"}' \
  http://127.0.0.1:8080/api/admin/payment/订单ID/reject
```

确认收款后订单进入待接单，主播侧才会收到。

### 3. 上传封面图与试听片段（清单 D1 的一半）

```bash
# 封面图
curl -s -b pc.cookie -F "file=@/路径/封面.jpg" \
  http://127.0.0.1:8080/api/admin/talents/主播ID/media/cover

# 试听片段
curl -s -b pc.cookie -F "file=@/路径/试音.mp3" \
  http://127.0.0.1:8080/api/admin/talents/主播ID/media/audio
```

传完回「主播管理」刷新，「素材」列应变成「齐全」。

### 4. 打赏金额上限（清单 D5）

```bash
curl -s -b pc.cookie -X PUT -H 'Content-Type: application/json' \
  -d '{"minCents":100,"maxCents":200000}' \
  http://127.0.0.1:8080/api/admin/tips/limits
```

现在是 ¥1 – ¥2000，我填的默认值。上限尤其该确认：两千块一笔的打赏，
风控与纠纷处理要跟得上。

打赏也要人工确认收款，接口是 `/api/admin/tips/{id}/confirm`，与订单同理。

### 5. 首页运营位（清单 A3，现已全部停用）

九条记录都还在，`enabled` 全是 0。补齐内容后逐条启用：

```bash
curl -s -b pc.cookie http://127.0.0.1:8080/api/admin/home-entries   # 看全部
```

更新某一条要带完整字段（title、subtitle、imageUrl、targetUrl、sortOrder、enabled），
见 `PUT /api/admin/home-entries/{id}`。

**启用前确认三件事**：`targetUrl` 指向真实页面、`imageUrl` 有图、
「新人首单立减」这类文案对应的券确实已经发出去了。

### 6. 月度结算报表

```bash
curl -s -b pc.cookie "http://127.0.0.1:8080/api/admin/settlement/monthly?period=2026-11"
```

## 三、建议补的页面

按「不补就没法运营」排序：

1. **待对账 + 确认收款**（阻断级：不补，线上没有任何订单能完成）
2. **收款配置**（上线前要填一次，之后换账号才用）
3. **主播素材上传**（录花名册时每个主播都要用，几十次 curl 不现实）
4. **打赏管理**（打赏同样需要人工确认收款）
5. **结算报表**（月底给主播结钱时要用）
6. **订单管理**（取消、退款等例外处理）
7. **首页运营位**
8. **满意度回访查看**

后端接口都在、都有测试覆盖，补的是页面。

---

## 四、建议的执行顺序

1. 先启动域名备案（周期最长）
2. 配服务项目与档位 → 给主播设价（第一部分 1）
3. 录主播文字资料（第一部分 2）+ 传封面与试听（第二部分 3）→ 确认齐全后上架
4. 填真实收款账号并转账验证（第二部分 1）
5. 定等级门槛、券档位、打赏上限（第一部分 4、5；第二部分 4）
6. 补齐或继续停用首页运营位（第二部分 5）
7. 部署上线（tasks 13.1 / 13.2），用真实微信账号端到端走一遍完整链路
