# 开局配置操作手册

把剩下的待办拆成可以照着做的步骤。日常运营（每天怎么对账、怎么处理纠纷）在
`docs/ops-runbook.md`，这一份只管**上线前把东西配起来**。

---

## 先说一件要紧的事：有几块运营能力没有后台页面

动手之前你得知道哪些事现在点得到、哪些点不到。我把后端的运营接口和后台实际
接入的页面逐一对了一遍：

| 要做的事 | 后端接口 | 后台页面 |
| --- | --- | --- |
| 主播文字资料、上下架 | 有 | ✅ 主播管理 |
| 服务项目与价格 | 有 | ✅ 服务与价格 |
| 分成比例 | 有 | ✅ 分成比例 |
| 优惠券 | 有 | ✅ 优惠券 |
| 粉丝等级门槛 | 有 | ✅ 粉丝等级 |
| 元子记账 | 有 | ✅ 元子记账 |
| 内容审核、心动墙 | 有 | ✅ 内容审核 |
| 会话查询 | 有 | ✅ 会话查询 |
| 转化看板 | 有 | ✅ 转化看板 |
| 填收款账号 | 有 | ✅ 收款与对账 → 收款配置（2026-11-20 补） |
| 每日待对账、确认收款 | 有 | ✅ 收款与对账 → 待对账 / 待支付（2026-11-20 补） |
| 上传封面图与试听片段 | 有 | ✅ 主播管理 →「素材」（2026-11-20 补） |
| **订单管理（取消、退款）** | 有 | ❌ **没有页面** |
| 打赏管理（确认、退款、取消、上限） | 有 | ✅ 打赏管理（2026-11-20 补） |
| **结算报表（月度分账）** | 有 | ❌ **没有页面** |
| **首页运营位** | 有 | ❌ **没有页面** |
| **满意度回访查看** | 有 | ❌ **没有页面** |

原本最要命的是收款那两行：**人工收款模式下，钱到账后订单不会自动往前走，
必须有人在后台点「确认收款」**；没有页面，线上任何一笔订单都会永远卡在待支付/
待确认，主播接不到单。`docs/ops-runbook.md` 第一章让运营「打开后台的待对账列表」，
而那个列表当时并不存在。

**这两项已于 2026-11-20 补上**，菜单「收款与对账」，见第一部分第 7 节。
表里剩下的 ❌ 仍然只能走 curl。

### 为什么一直没被发现

因为后端这些接口**全都有测试覆盖、而且都是走真实 HTTP 接口测的**。
第 14 组那八条端到端验收也一样：它们直接请求 `/api/admin/payment/{id}/confirm`，
接口返回什么、金额对不对、状态怎么流转，全都验到了。

但「这个接口在后台有没有一个按钮」，接口测试永远测不到。
我写验收用例时特意强调「不走捷径调 service，全部经过真实 HTTP 接口」——
这话没错，可它挡住的是服务层的接缝，不是前端缺页面。

下面的步骤里，**没有页面的事我给 curl 命令**，并标注这是临时办法。

## 一、现在就能在后台点的

后台地址 `https://你的域名/admin`，需要运营角色，在微信里打开。

### 1. 服务与价格（最先做，别的都依赖它）

菜单「服务与价格」。

1. **建服务项目**：填「编码」（英文短名，如 `listen`，建后不要再改——
   首页品类 Tab 按它筛选）、「名称」（如 情感倾听）、「说明」、「排序」。
2. **给项目建档位**：填「档位」编码、「名称」（如 30 分钟）、「时长」（分钟）、「排序」。
3. **给主播设价**：填「主播 ID」、选档位、填「单价」、置为启用。

> 价格在粉丝下单那一刻快照进订单，之后改价不影响已有订单。

### 2. 主播管理（文字资料部分）

菜单「主播管理」→「新建主播」。可填：昵称（必填）、性别、年龄、地区、简介、
宣传语标签（最多 2 条）、排序。

列表的「素材」列会标出「缺封面」「缺试听」，点同一行的「素材」按钮就能传，
见下面第 8 节。

建完先别急着上架。**上架前确认：有价格、有封面、有试听**，否则粉丝端卡片会留白。
上架用列表里的「上架」按钮。

### 3. 分成比例

菜单「分成比例」。默认 30%。改动**只影响此后的新订单**——已有订单的分成在下单
那一刻就快照了，不会被追溯修改。

### 4. 粉丝等级门槛

菜单「粉丝等级」。现在是我填的占位值，名字就叫 L1–L5：

| 等级 | 名称 | 累计消费门槛 |
| --- | --- | --- |
| 1 | L1 | 0 元 |
| 2 | L2 | 200 元 |
| 3 | L3 | 1000 元 |
| 4 | L4 | 3000 元 |
| 5 | L5 | 10000 元 |

改「名称」和「累计消费门槛（元）」即可。规则：等级 1 的门槛必须是 0，
门槛必须逐级递增。等级只影响展示，不影响下单价格与分成。

### 5. 优惠券

菜单「优惠券」→ 新建。填：券名、面额、使用门槛、有效期（生效 / 失效时间）。
建完在列表里「发放」，可发给全体粉丝或指定用户。

> 门槛按**订单原价**判定，券只减粉丝实付，主播分成一分不少，差额由公会承担。
> 单笔订单只能用一张券。

### 6. 心动墙

菜单「内容审核」→「心动墙」页签。按主播 ID 挑人、设排序。本阶段只有手工挑选。

### 7. 收款与对账（上线后天天要用）

菜单「收款与对账」，三个页签。

**收款配置**（上线前先做这个，清单 A1）

填收款名称、账号、开户行；有收款码就填图片地址。「付款提示」会原样展示在
粉丝的付款页，建议写上「转账时请在备注里填订单号」。

账号如果还是开发期留的占位值，页面顶部会直接标红提醒。
改完**自己转一笔小额过去验证真的能到账**，别只看页面显示正常。
改动只影响此后进入支付环节的订单，已经在付款页的订单仍看到旧信息。

**待对账**（每天固定时间做一次）

粉丝转账后上传凭证，订单停在「待确认收款」，列在这个页签里。
先核对银行/收款码的入账流水，再回到这里逐条处理：

- 对上了 → 「确认收款」。实收金额默认按应付填好，核对无误直接提交；
  流水号建议填，留空会自动用订单号兜底。
  **确认后订单才进入待接单，主播这时才看得到这一单。**
- 对不上 → 「驳回」，必须写原因。订单退回待支付，粉丝可以重新传凭证，
  原因会记在订单上。

实收与应付不一致时必须填差异说明。注意：**分成仍按订单原价算，不按实收重算**，
所以少收的差额是公会自己承担，确认前想清楚。

同一笔被点两次（比如两个人同时在对账）不会重复入账，第二次会提示
「这笔已经收过款了」。

**待支付**

粉丝还没传凭证的订单。如果钱其实已经到账（粉丝直接转了却没回来点上传），
可以在这里直接确认收款，不必等他补凭证，确认后同样推进到待接单。

### 8. 主播素材：封面图与试听片段（清单 D1 的一半）

菜单「主播管理」→ 对应那一行的「素材」按钮。录花名册时每个主播都要走一遍。

**封面图**

点「上传封面」选图即可，选完立刻上传。JPG / PNG / WebP，不超过 2 MB。
**建议用竖图**，粉丝端卡片和详情页都按竖向裁切，横图会被切掉两边。
格式或体积不对时选完就会提示，不会白传一遍。更换封面后旧文件会被自动删除。

**试听片段**

点「上传试听」选文件后**不会立刻上传**，会先显示读出来的时长让你确认：

- 时长是浏览器从文件里读出来的，**后端不解析音频**，这个数字直接决定粉丝端
  卡片上显示的秒数（例如「7″」）。读错了就在输入框里改。
- 个别文件读不出时长（损坏、没传完、或编码特殊），会提示让你自己听一遍手填。
  不填不让上传——宁可多问一句，也不要写一个错的秒数进去。

MP3 / M4A / AAC / WAV，不超过 5 MB。换新片段后旧文件同样会被删除。

传完弹窗里就能看到封面预览和可播放的试听条，列表的「素材」列会变成「齐全」。
已上架但素材不齐的主播，弹窗顶部会红字提醒——那种状态下粉丝端卡片正在留白。

### 9. 打赏管理（清单 D5 在这里改）

菜单「打赏管理」，三个页签。先说两件和订单不一样的事：

- **打赏确认收款后直接计为已完成**，不进待接单，主播什么也不用做。
- **打赏没有超时回收。** 订单的超时任务只管服务订单，打赏的支付截止时间到了
  也没人管。粉丝发起却不付款的记录会一直挂在待处理里，只能手工取消。

**待处理**

待支付和待确认收款合在一起——对你来说都是「还没入账、要我处理」。
每行带粉丝昵称、主播、金额、分成拆分和粉丝留言。

- 钱到账了 → 「确认收款」。实收默认按打赏金额填好。
  **分成在粉丝发起那一刻就按打赏金额算好固定了，不会按实收重算**，
  所以实收少了的差额是公会自己承担，备注里写清楚。
- 一直不付款 → 「取消」，原因必填。只能取消还没收款的；钱已经到账的要走退款。

**记录**

按已完成 / 已退款 / 已取消筛选。已完成的记录可以「标记退款」：

> 标记退款会**冲销结算台账**，并且**按这笔打赏当初计入的那个周期**从榜单扣回
> ——不是从本周期扣，否则上个月的账永远是错的。
> **钱要你自己转回去，系统不会代为退款。**

这个接口暂时没有分页，记录多了之后这一页会变慢。

**金额范围**

粉丝发起打赏时按这个范围校验，改动只影响此后发起的打赏。
现在是 ¥1 – ¥2000，我填的默认值。**上限尤其该确认过再上线**：
一笔两千块的打赏，风控与纠纷处理要跟得上，而退钱是人工转账。

## 二、后端有接口、但后台还没页面的

以下都要用命令行。**这是临时办法**，正式做法是把页面补上（见第三部分）。

先拿一个运营身份的会话 Cookie。本机开发环境：

```bash
UA="Mozilla/5.0 (iPhone; MicroMessenger/8.0.49)"
LOC=$(curl -s -i -c pc.cookie -A "$UA" \
  "http://127.0.0.1:8080/api/auth/wechat/authorize?redirect=/" \
  | grep -i '^Location:' | tr -d '\r' | sed 's/^Location: //')
curl -s -o /dev/null -b pc.cookie -c pc.cookie -A "$UA" "$LOC"
curl -s -b pc.cookie -A "$UA" http://127.0.0.1:8080/api/session/me
```

线上环境没有这个授权桩，得用真实微信登录后从浏览器里取 `PCSESSION` 的值，
后面的命令都带上 `-b "PCSESSION=取到的值"`。

> 填收款账号、每日对账与确认收款、主播封面与试听、打赏处置与金额范围
> **都已经有页面了**，不要再用 curl 做这几件事，见第一部分第 7、8、9 节。

### 1. 首页运营位（清单 A3，现已全部停用）

九条记录都还在，`enabled` 全是 0。补齐内容后逐条启用：

```bash
curl -s -b pc.cookie http://127.0.0.1:8080/api/admin/home-entries   # 看全部
```

更新某一条要带完整字段（title、subtitle、imageUrl、targetUrl、sortOrder、enabled），
见 `PUT /api/admin/home-entries/{id}`。

**启用前确认三件事**：`targetUrl` 指向真实页面、`imageUrl` 有图、
「新人首单立减」这类文案对应的券确实已经发出去了。

### 2. 月度结算报表

```bash
curl -s -b pc.cookie "http://127.0.0.1:8080/api/admin/settlement/monthly?period=2026-11"
```

## 四、建议的执行顺序

1. 先启动域名备案（周期最长）
2. 配服务项目与档位 → 给主播设价（第一部分 1）
3. 录主播文字资料（第一部分 2）+ 传封面与试听（第一部分 8）→ 确认齐全后上架
4. 填真实收款账号并转账验证（第一部分 7）
5. 定等级门槛、券档位、打赏金额范围（第一部分 4、5、9）
6. 补齐或继续停用首页运营位（第二部分 1）
7. 部署上线（tasks 13.1 / 13.2），用真实微信账号端到端走一遍完整链路
